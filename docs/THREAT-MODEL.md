# 威胁模型与未完成门槛

Harmonia 当前是实验性开源实现，尚未经过独立审计或完整平台验收，不能宣称生产可用。

服务器、网络观察者和通知通道不应获得环境明文或环境钥。每环境独立钥限制跨环境泄露；TLS 保护账号认证及元数据传输，E2EE 保护存储明文。服务器仍可观察账号目录、设备/环境标识、角色、序号、访问模式、密文长度和变量名。变量名属于可见元数据，测试和示例不要含个人资料。

RO 设备取得环境全部对称钥后能伪造 AEAD 密文，因此写删必须同时具备独立设备签名和当前管理授权。服务器逐次验证当前权限并原子维护代际、撤销、接受序号和幂等结果；客户端验证管理签名及可信公钥绑定。账号代际防旧会话/设备跨重置生效，持久化最高检查点防基本历史回放。没有外部见证系统，服务器隐藏最新更新或分叉历史仍超出当前保证。

被攻陷的授权设备可以泄露其已读取的数据。撤销、到期或轮换不能追回已知明文；旧恢复码与历史密文的组合也不能被追溯撤回。权限撤销本身不会使旧环境钥忘记；是否需要面向剩余设备轮换环境钥由管理流程执行，必须生成对应恢复封套。

密码派生值是可重放的密码等价凭据，不能泄露或误称为零知识登录。邮箱重置只能证明邮箱所有权并破坏性初始化新账号代际，不能恢复原 vault。丢失所有可信设备和恢复码意味着旧 vault 无法找回。恢复码不是数据备份。

手机系统密码或强生物认证保护本地软件钥，不能总是声称钥匙在硬件内。桌面开机无人登录服务需要服务可读钥保护，不能依赖登录后才解锁的 Keychain。完整磁盘加密和开机解锁仍是前置条件；root 或已解锁磁盘完全被攻陷的攻击者不在此保证之内。系统服务适配必须验证按本地用户隔离和最小权限。

当前必须明确保留的门槛：成熟 SPAKE2 集成与真实审批、公钥绑定和授权链端到端验收、完整恢复/轮换/邮箱重置、手机原生钥保护、虚拟机开机服务与 ACL 验证、Workers Argon2 实际资源测试、Workers/Docker 持久化原子性验收、安全邮件发送和独立审计。某个加密原语测试通过不代表这些门槛已通过。
